# Migration Guide: v5.7.0 to v5.8.0

This guide covers user-visible breaking changes in Cloudflare Python SDK v5.8.0.

## Address Maps account membership

`address_maps.accounts.update()` and `delete()` now identify the member account positionally and accept the address
map as a keyword argument.

Before:

```python
client.addressing.address_maps.accounts.update(
    "address-map-id",
    account_id="account-id",
    body={},
)
```

After:

```python
client.addressing.address_maps.accounts.update(
    "member-account-id",
    account_id="account-id",
    address_map_id="address-map-id",
)
```

Update both methods and pass the member account ID as the first argument.

## Removed empty request bodies

Several action endpoints no longer accept generated `body` parameters. Remove `body={...}` and obsolete parameter
type imports from calls to:

- account and user token value `update()`
- Address Maps IP and zone `update()`
- Cache Reserve `clear()`
- DNS record `scan()` and zone-transfer actions
- Email Routing `enable()` and `disable()`
- Access bookmark `create()` and `update()`
- Gateway certificate `activate()` and `deactivate()`

Before:

```python
client.email_routing.enable(zone_id="zone-id", body={})
```

After:

```python
client.email_routing.enable(zone_id="zone-id")
```

## Legacy WAF overrides and rate limits

Legacy WAF override and rate-limit methods now return `None`. Remove annotations and imports that depend on
`Override`, `OverrideDeleteResponse`, `RateLimit`, or `RateLimitDeleteResponse`. The WAF `WAFRule` and
`RewriteAction` response exports were also removed; use parameter types such as `WAFRuleParam` and
`RewriteActionParam` when constructing requests.

Before:

```python
from cloudflare.types.rate_limits import RateLimit

rate_limit: RateLimit = client.rate_limits.get("rate-limit-id", zone_id="zone-id")
```

After:

```python
client.rate_limits.get("rate-limit-id", zone_id="zone-id")
```

## Response type replacements

Update explicit imports and annotations for these resources:

- Hyperdrive config methods now use `ConfigCreateResponse`, `ConfigUpdateResponse`, `ConfigListResponse`,
  `ConfigEditResponse`, and `ConfigGetResponse` instead of `Hyperdrive`.
- mTLS certificate `list()`, `delete()`, and `get()` now use the shared `MTLSCertificate` type instead of
  operation-specific response types. `create()` still returns `Optional[MTLSCertificateCreateResponse]`.
- cache origin cloud region operations now use `OriginCloudRegionUpdateResponse`,
  `OriginCloudRegionListResponse`, and `OriginCloudRegionGetResponse`.
- `zero_trust.organizations.list()` now yields `OrganizationListResponse`.

## Pagination and optional responses

The following return types changed:

- `workers.scripts.deployments.list()`: `DeploymentListResponse` to
  `SyncV4PagePagination[DeploymentListResponse]`
- `zero_trust.gateway.lists.items.list()`: `SyncSinglePage` to `SyncV4PagePaginationArray`
- `zero_trust.gateway.pacfiles.list()`: `SyncSinglePage` to `SyncV4PagePaginationArray`
- `zero_trust.devices.override_codes.list()`: `SyncSinglePage[object]` to
  `Optional[OverrideCodeListResponse]`

Workers deployment, Gateway list-item, and Gateway PAC-file listings also accept new pagination controls. Workers
deployment listing adds `since` and `until` date filters.

Waiting Room operations now return `Optional[...]`. Check for `None` before accessing response fields:

```python
waiting_room = client.waiting_rooms.get("waiting-room-id", zone_id="zone-id")
if waiting_room is not None:
    print(waiting_room.name)
```

## Email Routing DNS

`email_routing.dns.delete()` now performs a DELETE request and returns `Optional[Settings]`. Code expecting an
iterable page of DNS records must switch to handling a single optional settings object. `dns.get()` is also
optional and returns `List[DNSRecord]` instead of the previous response-envelope union.

## Browser Rendering parameter variants

Browser Rendering create parameter types for URL/HTML-based endpoints are generated as unions. Requests to those
endpoints must provide either `url` or `html`; session endpoints such as `devtools.browser.create()` are unaffected.
If you directly import nested helper types such as `Viewport`, `Cookie`, or `PDFOptions`, update imports to the
corresponding generated variant namespace.

```python
client.browser_rendering.screenshot.create(
    account_id="account-id",
    url="https://example.com",
)
```

## Zero Trust Resource Library applications

`ApplicationCreateParams` is now a union of variants. Provide either `hostnames` or `ip_subnets` when creating an
application.

```python
client.zero_trust.resource_library.applications.create(
    account_id="account-id",
    name="Example application",
    hostnames=["example.com"],
)
```

## Pipelines schema fields

Replace per-response schema field imports with the shared field types:

- `SourceField`
- `SourceFieldParam`
- `ListField`
- `ListFieldParam`
- `StructField`
- `StructFieldParam`

## Rulesets generated symbols

Generated nested Rulesets type names were normalized. Examples include `BlockRule` to `RuleBlockRule`,
`CompressResponseRule` to `RuleResponseCompressionRule`, and `SetConfigRule` to
`RuleSetConfigurationRule`. Response rule fields such as `id`, `action`, `enabled`, `expression`, and `ref` are now
required; ensure manually constructed response fixtures include them.

## Required response fields

Calls SFU and TURN response fields including `created`, `modified`, `name`, `uid`, `secret`, and `key` are now
required. Flagship response `type` fields and Workers domain `environment` fields are also required. Update
manually constructed models and test fixtures accordingly.

## Magic Transit connectors

Remove `primary` and `site_id` from connector create/edit/update parameters and from response access.

## Removed exports

Remove or replace imports of:

- `cloudflare.types.stream.Clip`
- `cloudflare.types.stream.Playback`
- `cloudflare.types.stream.Watermark`
- `cloudflare.types.cache.State`

Nested types from the removed legacy rate-limit response models were also removed.

## R2 jurisdiction keyword

Rename `jurisdiction=` to `cf_r2_jurisdiction=` in R2 bucket, object, domain, lifecycle, lock, CORS,
event-notification, and Sippy calls.

Before:

```python
client.r2.buckets.list(account_id="account-id", jurisdiction="eu")
```

After:

```python
client.r2.buckets.list(account_id="account-id", cf_r2_jurisdiction="eu")
```

The new keyword also accepts `fedramp-high`.

## Firewall bulk operations

Firewall rule bulk edit/update parameters now require an `id` instead of a `body` collection. Update calls and
replace imports of `RuleBulkEditParams.Body` or `RuleBulkUpdateParams.Body`.

WAF package retrieval now returns a raw optional string/object union instead of wrapped
`FirewallAPIResponseSingle` and `Result` models.

## Cloud Connector rules

`RuleUpdateParams.rules` is now required. Always supply the full rule collection when updating Cloud Connector
rules.

## Hyperdrive parameter variants

`ConfigCreateParams` is now a union of origin and integration variants. Direct imports of create-parameter helper
types such as `Origin`, `Caching`, and `MTLS` must move to the generated variant types. The integration variant
requires its provider-specific fields.

## Enum narrowing

Update code that handles these removed enum members:

- Email Security bulk-job status `SKIPPED`
- Email Security message status `DISCOVERING`
- CASB remediation vendors `Okta` and `Workday`

Email Security bulk responses now require `messages_cancelled` and `messages_skipped`.

## Optional fields

Handle `None` for AI Search namespace `created_at`, selected billing usage fields, Workers observability
`request_id`, and Access Browser RDP/Infrastructure `target_attributes` response fields.

## Additional response-shape changes

- URL Scanner robots rules now use a dictionary keyed by rule name.
- DLS prefix-binding response messages/errors now use shared `ResponseInfo` entries.
- Selected Radar date/time and numeric values now use `date`/`datetime` and `int` instead of `str` and `float`.
- Realtime Kit session participant `per_page` is now an `int`.

## Summary

1. Update Address Maps account arguments and R2 jurisdiction keywords.
2. Remove obsolete request bodies and update required request fields.
3. Update changed response, pagination, enum, and scalar annotations.
4. Handle new optional responses and fields.
5. Update variant-based Browser Rendering, Hyperdrive, and Resource Library parameters.
6. Replace renamed or removed exported types.
